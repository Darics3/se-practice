# User stories — Smart Campus study room booking

### US-01
**Story:** As a Student, I want to view room availability, so that I can see which rooms are free and when.
**Priority:** High
**Assumption:** Availability reflects existing bookings and whether a room is blocked.

### US-02
**Story:** As a Student, I want to book a free room for a time slot, so that I can reserve it for individual or group study.
**Priority:** High
**Assumption:** The booking must satisfy R1–R4 before it can be created.

### US-03
**Story:** As a Student, I want to cancel a booking I made, so that the reserved room and time slot become available again.
**Priority:** High
**Assumption:** A Student can cancel only a reservation that they made.

### US-04
**Story:** As an Administrator, I want to block or unblock a room, so that rooms can be taken out of service and later returned to use.
**Priority:** High
**Assumption:** A blocked room cannot be booked according to R4.

### US-05
**Story:** As an Administrator, I want to review room usage over a period, so that I can understand how study rooms are being used.
**Priority:** Medium
**Assumption:** Usage information is based only on booking information available within this system.

### US-06
**Story:** As a Student, I want to receive confirmation after a booking or cancellation, so that I know the requested action was completed.
**Priority:** High
**Assumption:** Confirmation is produced only for a completed booking or cancellation.
